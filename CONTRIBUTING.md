# Contributing

First off — thanks for considering contributing! This project only works if people like you share what they've learned. 🙌!

<br/>

## What you can contribute

- **Tips** — a piece of advice that helped you (or someone you know) at a hackathon. Add it under "Key tips from people I know."
- **Brainstorming notes** — thoughts, quotes, or frameworks about how to brainstorm and pick problem statements.
- **Personal experiences** — a short writeup of a hackathon you took part in: what went right, what went wrong, what you'd do differently.
- **Resources** — curated links to problem statement lists, judging criteria breakdowns, pitch deck templates, or similar tools you found useful (with attribution — see below).
- **Fixes** — typos, broken links, formatting issues.

If you're not sure whether something fits, open an issue first and ask.

## How to contribute

1. **Fork** the repo and create a new branch (e.g. `add-tip-time-management`).
2. **Make your change** in `README.md` (or a new file, if you're adding a bigger resource — see "Growing the repo" below).
3. **Keep entries short and skimmable.** One tip = one bullet. One experience = a few sentences or a short section, not a full essay, unless it's genuinely a deep-dive (in which case, put it in its own file under `/experiences/`).
4. **Attribute sources.** If a tip, quote, or resource comes from someone else or another repo (for example, linking out to a curated problem-statement list), credit them by name/handle and link to the original.
5. **Open a Pull Request** with a short description of what you added and why it's useful.
6. A maintainer will review, may suggest edits, and merge.

## Style guide

- Use bullet points for tips, not paragraphs.
- Use `>` blockquotes for standalone quotes or brainstorming prompts.
- Keep section headers consistent with the existing ones (`### Key tips from people I know`, `### Brainstorming`, `### Personal Experiences`) unless proposing a new section — propose new sections via an issue first.
- Write in plain, first-person, conversational language. This isn't a formal doc — it's meant to read like advice from a friend who's been through it.

## Growing the repo

Right now everything lives in one README. As it grows, contributions that would make sense as their own files include:

- `/experiences/` — one markdown file per detailed hackathon writeup.
- `/resources.md` — curated external links (problem statement banks, pitch templates, judging rubrics), similar in spirit to lists like [AshayK003/hackathon-problem-statements](https://github.com/AshayK003/hackathon-problem-statements).

If you want to propose a new structure like this, open an issue titled `[proposal] ...` so it can be discussed before a big restructuring PR.

## Questions

Open an issue or start a discussion — happy to help first-time contributors figure out where their content fits.
